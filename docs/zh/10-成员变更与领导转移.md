# 10. 成员变更与领导转移

> **导航：** [← 09. Session 与 CLI 幂等](./09-Session与CLI幂等.md) · [11. 快照与落后追赶 →](./11-快照与落后追赶.md) · [索引](./README.md)

本实现使用 **联合共识（Joint Consensus）** 做成员变更，并支持 **通过配置去掉当前领导** 实现 step down。源码：`src/raft/membership.rs`、Leader `propose_membership_change` / `maybe_propose_simple_after_joint`。

---

## 1. 配置类型

```text
Membership { voters: BTreeSet<NodeID> }

MembershipEntry::Simple(Membership)           // 单一配置
MembershipEntry::Joint { old, new }           // 联合：两套多数都要满足
```

| 阶段 | 法定人数 |
|------|----------|
| Simple(C) | C 的严格多数 |
| Joint(Cold, Cnew) | **Cold 多数且 Cnew 多数** |

`MembershipState`：

- `active`：当前生效条目（**一追加进日志就切换**，不必等提交）  
- `change_pending`：是否有在途变更（一次只允许一个）  

---

## 2. 客户端 API

```text
Request::ChangeMembership { voters: HashSet<NodeID> }  // 目标 C_new
Response::ChangeMembership { index }                   // 通常是 Joint 条目索引
```

CLI：

```bash
cargo run --bin raft-cli -- --peers ... members 1,2,3,4
```

---

## 3. 变更流程（Leader）

```text
1. 拒绝条件：
   - 已有 change_pending / 已在 Joint
   - voters 空
   - 与当前 Simple 相同
2. 取 old = 当前 Simple
3. 提出 Joint { old, new: C_new } → append_membership
4. apply_entry(Joint)  // 立刻双多数
5. 复制；双多数提交 Joint
6. on_commit(Joint) 后自动 maybe_propose_simple_after_joint
7. 提出 Simple(C_new) → 追加即生效
8. Simple 提交 → change_pending=false
9. 若 self ∉ C_new → step_down（领导转移完成）
```

### 日志中的条目

```text
Entry {
  command: None,
  membership: Some(Joint { old, new }),
}
// 随后
Entry {
  command: None,
  membership: Some(Simple(new)),
}
```

apply 时对状态机当 **noop**（推进 `applied_index`），客户端在 **Joint 提交时** 即可收到 `ChangeMembership{index}`（实现选择）。

---

## 4. 何时生效？

| 事件 | 配置指针 |
|------|----------|
| Joint **追加**到本地日志 | 立刻用双多数算选举/提交/读确认 |
| Joint **提交** | 自动再提 Simple |
| Simple **追加** | 立刻只用 C_new |
| Simple **提交** | pending 清除；可 step down |

Follower 在 `Append` 的 `splice` 后调用 `maybe_apply_membership_from_entries`，与 Leader 一样**日志出现即切换**。

---

## 5. 加节点 / 删节点

### 5.1 添加

1. 运维启动新 `raft-node`（空或追日志的 data_dir）  
2. 客户端 `members` 包含新旧全部 id  
3. 领导给新节点复制日志（过旧则 InstallSnapshot，见 11）  
4. 新节点进入 C_new 后参与多数  

进程内测试用 `Cluster::start(id)` 模拟拉起空日志节点。

### 5.2 删除（非领导）

`members` 去掉某 id → Joint → Simple 后，该 id 不再计入 quorum；实现不再向其 progress 复制（`sync_progress_with_membership`）。

### 5.3 删除当前领导（领导转移）

```text
C_old = {1,2,3}, Leader=1
ChangeMembership {2,3}
  → Joint 双多数（仍可能需要 1 的票，因 old 含 1）
  → Simple{2,3} 提交后
  → 节点 1: self ∉ voters → into_follower（同 term 下台）
  → {2,3} 选出新领导
```

**本实现没有单独的 TimeoutNow / 传领导 RPC**；靠成员变更把旧领导移出配置。

---

## 6. 各角色在变更期间

| 角色 | 行为 |
|------|------|
| Leader | 唯一提出配置条目；维护 progress 集合变化 |
| Follower | 复制配置条目；追加后改 active |
| Candidate | 用 **当前 active**（可能是 Joint）算票是否够双多数 |

## 8. 源码锚点

| 步骤 | 位置 |
|------|------|

| 自动 Simple | `maybe_propose_simple_after_joint` |
