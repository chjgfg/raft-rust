# 03. 选举全流程

> **导航：** [← 02. 消息与数据结构](./02-消息与数据结构.md) · [04. 数据存取全流程 →](./04-数据存取全流程.md) · [索引](./README.md)

本文按**时间顺序**说明：节点从 Follower 超时，经 Pre-vote、真选举，到成为 Leader；以及过程中 **term / 投票 / 日志** 如何变化。源码：`src/raft/node.rs`、`log.rs`、`membership.rs`。

---

## 1. 前提与时钟

| 概念 | 本实现 |
|------|--------|
| 逻辑时钟 | `tick()`，约每 100ms 一次（`TICK_INTERVAL`） |
| 选举超时 | 节点启动时在 `election_timeout_range` 内随机（配置里常 5..10 tick） |
| 心跳间隔 | Leader 每 `heartbeat_interval` tick 广播 Heartbeat（配置常为 2） |
| 持久化 | 真选举的 term/vote 写 `Key::TermVote` 并 **总是 fsync** |

单节点（`peers` 为空）：`Node::new` 直接 `into_candidate(false)` → `into_leader()`，**跳过 Pre-vote 等待**。

---

## 2. 角色状态机（概览）

```text
                    选举超时
         ┌──────────────────────────┐
         │                          ▼
    ┌────┴─────┐   预选获多数    ┌──────────┐   真选获多数   ┌────────┐
    │ Follower │ ─────────────► │Candidate │ ────────────► │ Leader │
    │          │                │ PreVote  │               │        │
    └────▲─────┘                │    ↓     │               └────┬───┘
         │                      │ Election │                    │
         │   收到合法 Leader 消息 │          │                    │
         │   或更高 term          └────┬─────┘                    │
         │                            │ 失败/超时再来            │
         └────────────────────────────┴────────────────────────┘
              更高 term / CheckQuorum 下台（Leader→无主 Follower）
```

`Candidate` 内部相位：

```rust
enum ElectionPhase { PreVote, Election }
```

## 3. 阶段 0：稳定运行（有 Leader）

假设三节点 `{1,2,3}`，当前 **Leader=2，term=5**。

### 3.1 各节点在干什么

| 节点 | 角色 | 每 tick | 收到消息 |
|------|------|---------|----------|
| 2 | Leader | `since_heartbeat++`；到间隔则 `heartbeat()`；CheckQuorum 看 `peer_seen` | 处理 Append/读/写响应 |
| 1,3 | Follower | `leader_seen++`；若仍小于超时则**不竞选** | Heartbeat：清零 `leader_seen`，可能推进 commit 并 apply |

### 3.2 Leader 发出的心跳（结构）

```text
Envelope {
  from: 2, to: 1, term: 5,
  message: Heartbeat {
    last_index:   领导者日志最后索引,
    commit_index: 已提交索引,
    read_seq:     当前读序号,
  }
}
```

Follower 回复：

```text
HeartbeatResponse { match_index, read_seq }
```

- 若本地日志在 `last_index` 处 term 匹配 → `match_index = last_index`  
- 否则 `match_index = 0`（触发 Leader 探测/复制）

### 3.3 此阶段数据变化

| 数据 | 变化 |
|------|------|
| term/vote（磁盘） | **不变** |
| Raft 日志 | 仅 Leader 写新客户端条目时增长；Follower 经 Append 追上 |
| Kv 内存 | commit 推进后 `apply` |
| 角色 | 保持 |

## 4. 阶段 1：Follower 选举超时

假设节点 **1** 一段时间收不到 2 的消息（网络分区或 Leader 崩溃）。

### 4.1 tick 序列

```text
tick: leader_seen = 1, 2, 3, ... 
直到 leader_seen >= election_timeout
  → into_candidate(use_prevote = opts.pre_vote)
```

`into_candidate` 时会：

1. **`abort_forwarded()`**：所有正在转发的客户端请求 → `ClientResponse{Abort}`  
2. **`maybe_apply()`**：尽量应用已提交日志  
3. 若 `pre_vote`：进入 **PreVote** 相位并 `pre_campaign()`  
4. 若关闭 pre_vote：直接 `campaign()` 真选举  

### 4.2 节点变化

| 项目 | 变化前 | 变化后 |
|------|--------|--------|
| 角色 | Follower(leader=Some(2)) | Candidate(phase=PreVote) |
| term（持久化） | 5 | **仍为 5**（预选不抬 term） |
| vote | 可能 Some(2) 或本 term 已投票 | **预选不改** |
| forwarded | 可能非空 | 清空（已 Abort） |

---

## 5. 阶段 2：Pre-vote（预选）

### 5.1 节点 1 发出什么

```text
// 对 peer 2、3 各一条
Envelope {
  from: 1,
  to: 2 或 3,
  term: 6,                    // intended = 当前 term + 1，仅放在信封上
  message: PreCampaign {
    last_index: 1 的最后日志索引,
    last_term:  1 的最后日志任期,
  }
}
// votes 初始含自己 {1}
```

**重要：** 磁盘上的 term **仍是 5**。`Envelope.term=6` 只表示「我想竞选的 term」。

### 5.2 其它节点收到 PreCampaign 时

处理函数：`Follower::step_prevote`（**不会**因更高 term 切换任期）。

授予预选票条件（同时）：

1. **未与当前领导保持联系**  
   - 若 `leader.is_some()` 且 `leader_seen < election_timeout` → **拒绝**（领导还活着）  
2. **日志够新**  
   - 候选人 `(last_term, last_index)` ≥ 本地最后条目  
3. **`msg.term > self.term()`**  
   - intended 必须大于本地持久化 term  

响应：

```text
PreCampaignResponse { vote: true/false }
```

| 节点行为 | 落盘？ | 改角色？ |
|----------|--------|----------|
| 回预选票 | **否** | **否** |
| 拒绝预选票 | 否 | 否 |

### 5.3 节点 1 收齐预选票

```text
votes ⊇ 多数（含自己）→ 日志 "Pre-vote won" → campaign()
```

若预选失败：选举超时后再次 `pre_campaign()`（仍不抬持久化 term，或仅刷新 intended）。

### 5.4 预选阶段「不干什么」

- **不** `set_term_vote`  
- **不** 复制日志  
- **不** 服务客户端（Candidate 对 ClientRequest 一律 Abort）  
- 分区出去的落后节点：预选拿不到多数 → **无法抬 term 骚扰** 稳定多数派（这就是 Pre-vote 的意义）

## 6. 阶段 3：真选举 Campaign

### 6.1 `campaign()` 逐步

```text
1. term := term + 1          // 例如 5 → 6
2. phase := Election
3. votes := {self}
4. log.set_term_vote(6, Some(1))   // 落盘 + fsync
5. 广播 Campaign { last_index, last_term }  // Envelope.term = 6
```

### 6.2 磁盘数据变化（节点 1）

| 键 | 旧值（例） | 新值 |
|----|------------|------|
| `TermVote` `[0x01]` | `(5, Some(2))` 或 `(5, None)` | **`(6, Some(1))`** |

### 6.3 Follower 收到 Campaign

同 term 或先经更高 term 变成 Follower 后：

```text
若本 term 已投给别人 → CampaignResponse{false}
若本地日志更新       → CampaignResponse{false}
否则:
  set_term_vote(6, Some(1))   // 落盘
  CampaignResponse{true}
```

**日志够新规则**（拒绝若）：

```text
local.last_term > cand.last_term
或 (相等 且 local.last_index > cand.last_index)
```

### 6.4 节点 2、3 若仍认为 2 是领导

- 若它们**持续收到** 2 的心跳，可能已在预选阶段拒了 1  
- 若 2 已死：它们会更新 term=6 并可能投票给 1，或自己也超时进入选举  

### 6.5 获多数 → `into_leader()`

```text
votes 达 quorum
  → into_leader()
  → propose(None)           // 追加本任期 noop Entry
  → maybe_commit_and_apply  // 单节点可立刻提交 noop
  → heartbeat()             // 宣布领导权
```

## 7. 阶段 4：当选后的数据与角色

### 7.1 新 Leader（节点 1）内部

| 结构 | 初值 |
|------|------|
| `progress[peer].next_index` | `last_index+1` |
| `progress[peer].match_index` | `0` |
| `progress[peer].read_seq` | `0` |
| `peer_seen[peer]` | `0` |
| 日志 | 多一条 `Entry{term=6, command=None}`（noop） |

### 7.2 其它节点变为 Follower

收到 term=6 的 Heartbeat/Append：

```text
into_follower(6, Some(1)) 或 先无主再认主
leader = Some(1)
leader_seen = 0
```

### 7.3 对比表：选举前后

| | 选举前（例） | 选举后（例） |
|--|--------------|--------------|
| Leader | 2 | **1** |
| term | 5 | **6** |
| 节点1 角色 | Follower → Candidate | **Leader** |
| 节点2 角色 | Leader 或失联 | Follower 或下线 |
| 节点3 角色 | Follower | Follower(leader=1) |
| 已提交日志 | 不变（安全性） | 可继续追加 |
| 未提交分叉 | 可能被新主覆盖 | splice 修复 |

## 8. CheckQuorum：Leader 主动下台

不必等别人发起选举。Leader 每个 tick：

```text
peer_seen[p] += 1
若 check_quorum 且 节点数 > 1:
  window = election_timeout 上界
  活跃集 = {self} ∪ {p | peer_seen[p] < window}
  若活跃集构不成 quorum:
    into_follower(当前 term)   // 不抬 term
    在途客户端请求全部 Abort
```

收到 peer 的有效响应时 `peer_seen[p]=0`。

**效果：** 网络分区后，**少数派里的旧 Leader** 会自己下台，避免一直接受写却无法提交（提交本身也要多数；下台让语义更干净）。

## 9. 时序总图（三节点，节点1 当选）

```text
时间 →

N1 Follower          Candidate(PreVote)     Candidate(Election)      Leader
   | leader_seen++         |                      |                      |
   | timeout               | PreCampaign(t=6)     |                      |
   |                       |--------------------► |                      |
   |                       |  PreCampaignResp     |                      |
   |                       |◄-------------------- |                      |
   |                       | 多数预选票            |                      |
   |                       | campaign() term=6    |                      |
   |                       | 落盘 vote=1          |                      |
   |                       | Campaign             |                      |
   |                       |--------------------► |                      |
   |                       |  CampaignResp true   |                      |
   |                       |◄-------------------- |                      |
   |                       | 多数真选票            |                      |
   |                       | into_leader          |                      |
   |                       | noop + heartbeat     |                      |
   |                       |--------------------------------------------►|
   |                       |                      |   Heartbeat term=6   |
N3 Follower ─────────────────────────────────────► Follower(leader=1)    |
```

## 10. 消息与落盘对照（选举专用）

| 步骤 | 网络消息 | 磁盘 TermVote | 磁盘 Entry |
|------|----------|---------------|------------|
| 预选发出 | PreCampaign | 不变 | 不变 |
| 预选响应 | PreCampaignResponse | 不变 | 不变 |
| 真选开始 | Campaign | **term+1, vote=self** | 不变 |
| 收到选票 | CampaignResponse | 投票方可能已写 vote | 不变 |
| 当选 | Heartbeat / Append(noop) | 不变 | **追加 noop** |

---

## 11. 源码锚点

| 步骤 | 函数（约） |
|------|------------|
| Follower 超时 | `RawNode<Follower>::tick` → `into_candidate` |
| 预选 | `pre_campaign` / `step_prevote` |
| 真选 | `campaign` / `Campaign` 处理 |
| 当选 | `into_leader` |
| 下台 | `Leader::tick` CheckQuorum；或更高 term 的 `into_follower` |
