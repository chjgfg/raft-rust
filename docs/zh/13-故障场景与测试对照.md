## 1. 场景矩阵

| 场景 | 期望行为 | 主要测试 |
|------|----------|----------|
| 正常三节点读写 | 选主、put/get | `tests/cluster.rs` |
| 杀 Leader | 新主选出；已提交数据仍在 | `fault_leader.rs` |
| 少数派分区 | 少数不能提交；多数可写；愈合后一致 | `fault_partition.rs` |
| Pre-vote 隔离节点 | 少数抬不起有效领导、少骚扰 | `prevote_checkquorum.rs` |
| CheckQuorum | 孤立领导 step down | 同上 |
| 丢包 / 乱序 | 最终仍可选主可写 | `transport_unreliable.rs` |
| 并发客户端 | 无 panic；键最终可见 | `concurrent_clients.rs` |
| 写后读 | 写成功后读到 | `linearizable_read.rs` |
| 成员变更 | 加/删节点；数据保留 | `membership.rs` |
| 去掉当前领导 | 旧主 step down；新主可写 | `remove_leader_steps_down` |
| 重启（BitCask） | 同路径再开数据在 | `restart_and_snapshot.rs` |
| 快照后重启 | compact 后仍可读全量 | 同上 |
| 真多进程 TCP | 子进程 raft-node + CLI 协议 | `multi_process.rs` |
| Session 去重 | 同 seq 不双执行；旧 seq 不串结果 | `session_and_file.rs` |
| 确定性选举 | 无网络线程 step/tick | `node_unit.rs` |

## 2. 杀主（Leader 崩溃）

```text
1. 集群正常，put 已提交
2. stop(leader) 或杀 raft-node 进程
3. 其余节点 election timeout → Pre-vote → Campaign
4. 新 Leader 日志含已提交前缀（选举限制保证）
5. get 仍返回已提交值；可继续 put
```

进程内：`Cluster::stop(id)`。  
多进程：杀对应 OS 进程；数据在 `data_dir`，重启可再加入（需成员仍包含它）。

---

## 3. 网络分区

```text
partition {1} | {2,3}

少数 1：
  - 若曾是领导 → CheckQuorum 下台或无法多数提交
  - put 到 1 → Abort/超时
多数 2,3：
  - 可选新主或保持主
  - put 成功

heal_all 后：
  - 日志对齐；无多数提交的少数写不出现
  - 多数已提交的键全局可见
```

Pre-vote：分区出去的节点反复预选，**拿不到多数**则不会无意义抬 term 打断稳定多数（见 03）。

---

## 4. 日志分叉（概念）

旧主在少数区 append 未提交条目 → 新主在同 index 不同 term 写入 → 愈合后：

```text
Append/probe → splice 截断旧尾 → 以新主为准
```

详见 [07](./07-日志复制与冲突修复.md)。集成侧更多验证「愈合后与多数一致」，底层单测可构造分叉。

---

## 5. 重启恢复

### 5.1 无快照 / 未 compact

```text
BitCask 文件保留 Entry + TermVote + CommitIndex
启动 → Log::new 加载
→ 空 Kv + SessionState
→ maybe_apply 从 applied(0) 重放到 commit
→ 业务键恢复
```

### 5.2 有 SnapshotData

```text
restore(SnapshotData, last_included)
→ maybe_apply 只重放 first_index..=commit 的尾部
```

测试：`restart_replays_log_and_restores_kv`、`snapshot_compact_then_restart`。

---

## 6. 丢包与乱序（进程内）

| API | 效果 |
|-----|------|
| `set_drop_rate(p)` | 随机丢 Envelope |
| `set_reorder(true)` | 简单乱序缓冲 |
| `partition` / `heal` | 断连 / 恢复 |

期望：最终仍能选主并收敛（非实时时限保证）。

## 7. 真多进程测试注意

```bash
cargo build --bin raft-node
cargo test --test multi_process
```

测试会：

- 写临时 YAML + data_dir  
- spawn `target/debug/raft-node`  
- 经 TCP `WireMsg` 做 status/put/get  
- Drop 时 kill 子进程
