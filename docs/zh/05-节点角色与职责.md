# 05. 节点角色与职责

> **导航：** [← 04. 数据存取全流程](./04-数据存取全流程.md) · [06. BitCask 与日志键空间 →](./06-BitCask与日志键空间.md) · [索引](./README.md)

对照表：三种角色在**选举、复制、客户端、存储**上各自**做什么 / 不做什么**。

---

## 1. 总表

| 职责 | Follower | Candidate | Leader |
|------|:--------:|:---------:|:------:|
| 发起 Pre-vote / 真选举 | 超时后转 Candidate | **是** | 否 |
| 持久化投票 | 授真选票时 | 投自己时 | 更高 term 时清空 |
| 发送 Heartbeat / Append | 否 | 否 | **是** |
| 接受并写入复制日志 | **是**（splice） | 收到合法领导消息则先变 Follower | 自己 append |
| 提交日志（定 commit_index） | 跟随领导通知 | 否 | **是**（多数） |
| apply 状态机 | **是**（按 commit） | 切换前 `maybe_apply` | **是** |
| 处理客户端写 | 仅转发 | Abort | **propose** |
| 处理客户端读 | 仅转发 | Abort | **read_seq 多数后 read** |
| CheckQuorum 下台 | 否 | 否 | **是** |
| 服务线性一致读 | 否（不读本地当答案） | 否 | **是** |

---

## 2. Follower 详解

### 2.1 干什么

1. **计时**：`leader_seen`；超时 → Candidate  
2. **跟领导**：Heartbeat / Append / Read / InstallSnapshot  
3. **投票**：Campaign（真选）时按规则投票并落盘  
4. **预选票**：PreCampaign 时不落盘  
5. **写日志**：`Append` 成功则 `splice` 进本地 BitCask  
6. **应用**：commit 推进后 `State::apply`  
7. **转发客户端**：有 `leader` 则把 `ClientRequest` 发给领导  

### 2.2 不干什么

- 不主动 `append` 客户端写到日志  
- 不决定集群 `commit_index`（只跟随）  
- 不把本地 `Kv` 直接当线性一致读结果返回客户端  
- 无领导时不「猜」写成功（直接 Abort）  

### 2.3 内部数据

| 字段 | 含义 |
|------|------|
| `leader` | 当前认的领导 |
| `leader_seen` | 距上次领导消息的 tick |
| `election_timeout` | 超时阈值 |
| `forwarded` | 已转发未完成的 RequestID |

---

## 3. Candidate 详解

### 3.1 干什么

| 相位 | 行为 |
|------|------|
| **PreVote** | 广播 PreCampaign；数预选票；**不**改持久化 term |
| **Election** | `term+1`、投自己、广播 Campaign；数真选票 |
| 超时 | 再 pre_campaign 或 campaign |
| 收到合法领导消息 | 变 Follower 并处理该消息 |

### 3.2 不干什么

- 不复制业务日志（不当领导）  
- 不接受客户端读写（一律 Abort）  
- PreVote 相位不 `set_term_vote`  

### 3.3 内部数据

| 字段 | 含义 |
|------|------|
| `votes` | 已获票节点集合（含自己） |
| `phase` | PreVote / Election |
| `election_duration` / `election_timeout` | 本轮选举计时 |

---

## 4. Leader 详解

### 4.1 干什么

1. **心跳**：维持权威、推进 follower commit、携带 read_seq  
2. **写**：`propose` → 本地日志 → Append → 多数 → commit → apply → 回客户端  
3. **读**：分配 `read_seq`，多数确认后 `state.read`  
4. **进度**：每 peer `match_index` / `next_index`；冲突则 probe  
5. **成员变更**：提出 Joint，提交后自动 Simple；可 step down  
6. **快照**：阈值到则 compact；peer 太旧则 InstallSnapshot  
7. **CheckQuorum**：多数沉默则下台并 Abort 在途请求  

### 4.2 不干什么

- 不处理「别人当领导」的同 term Heartbeat（丢弃/warn，本实现不 panic）  
- 不把未达多数的写标为成功  
- 不在 apply 前向客户端返回写成功  

### 4.3 内部数据

| 字段 | 含义 |
|------|------|
| `progress` | 复制水位 |
| `writes` / `membership_writes` | 等待 apply 的客户端 |
| `reads` / `read_seq` | 线性读流水线 |
| `peer_seen` | CheckQuorum |
| `since_heartbeat` | 心跳节奏 |

---

## 5. 按场景的「谁动数据」

### 5.1 选举中

| 数据 | Follower | Candidate | Leader(旧) |
|------|----------|-----------|------------|
| TermVote 磁盘 | 可能投票写入 | 投自己写入 | 失联或更高 term 清空 |
| Entry 日志 | 通常不变 | 不变 | 可能仍 append（若未下台） |
| Kv | 仅 apply 已提交 | 切换前 apply | 同左 |

### 5.2 稳态写

| 数据 | Leader | Follower |
|------|--------|----------|
| Entry | 先写 | Append 后写 |
| CommitIndex | 多数后写 | Heartbeat 后跟 |
| Kv | apply 后更新 | commit 后 apply |

### 5.3 稳态读

| 数据 | Leader | Follower |
|------|--------|----------|
| 日志 | 不动 | 不动 |
| Kv | **只读** | 不参与回答（只回 ReadResponse 确认领导） |

---

## 6. 物理进程 vs 逻辑角色

`raft-node` **进程**始终在跑事件循环；**角色**在 `Node` 枚举间切换：

```text
同一进程:
  select! tick / 入站 / 出站
  node = node.step(...)  // 可能 Follower→Candidate→Leader
```

客户端永远连的是 **TCP 端口**，不绑定角色；角色变化只影响消息处理分支。
