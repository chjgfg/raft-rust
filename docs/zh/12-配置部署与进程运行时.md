# 12. 配置部署与进程运行时

> **导航：** [← 11. 快照与落后追赶](./11-快照与落后追赶.md) · [13. 故障场景与测试对照 →](./13-故障场景与测试对照.md) · [索引](./README.md)

本文说明 **YAML 配置**、**单/多进程怎么起**，以及 **`raft-node` / `raft-cli` 进程内部循环**。源码：`src/config.rs`、`src/bin/raft_node.rs`、`src/bin/raft_cli.rs`、`src/net/`。

---

## 1. 配置文件形态

每个 **OS 进程一份** YAML（不是一份文件管全集群）。

### 1.1 字段

| 字段 | 含义 |
|------|------|
| `node.id` | `NodeID`（u8），集群内唯一 |
| `node.listen` | 本机 `ip:port`，收 peer + CLI |
| `node.data_dir` | 数据目录；BitCask 文件为 `{data_dir}/bitcask.log` |
| `peers` | `[{id, addr}, ...]`；**空 = 单节点** |
| `options.*` | 见下表 |

### 1.2 options

| 键 | 含义 | 常见值 |
|----|------|--------|
| `heartbeat_interval` | 心跳间隔（tick） | 2 |
| `election_timeout_min/max` | 选举超时随机范围 | 5 / 10 |
| `max_append_entries` | 单次 Append 最多条 | 100 |
| `pre_vote` | 预选 | true |
| `check_quorum` | 领导丢多数下台 | true |
| `snapshot_threshold` | 多少条 apply 后 compact；0 关 | 1000 |

逻辑 tick ≈ 100ms（`TICK_INTERVAL`）。

### 1.3 示例路径

| 文件 | 用途 |
|------|------|
| `config/single.yaml` | `peers: []`，立即 Leader |
| `config/node1.yaml` … `node3.yaml` | 三节点互指 |

## 2. 部署方式

### 2.1 单节点

```bash
cargo run --bin raft-node -- --config config/single.yaml
# 或 default-run
cargo run -- --config config/single.yaml

cargo run --bin raft-cli -- --peers 127.0.0.1:7001 put a 1
```

### 2.2 三节点

三个终端：

```bash
cargo run --bin raft-node -- --config config/node1.yaml
cargo run --bin raft-node -- --config config/node2.yaml
cargo run --bin raft-node -- --config config/node3.yaml
```

CLI 建议写满 peer 列表，便于 Abort 时换节点：

```bash
cargo run --bin raft-cli -- --peers 127.0.0.1:7001,127.0.0.1:7002,127.0.0.1:7003 status
```

也可以只连一个地址（从节点会转发）。

## 3. raft-node 运行时

### 3.1 启动

```text
1. 解析 --config
2. NodeFileConfig::load
3. create_dir_all(data_dir)
4. BitCask::new(data_dir/bitcask.log)
5. 读 SnapshotData；restore 状态机（若有）
6. Log::new(engine)
7. SessionState::new(Kv::new())
8. Node::new(id, peer_ids, log, state, node_tx, opts)
9. spawn_listener(listen) → Inbound 通道
10. PeerOutbox(peers 地址表)
11. 进入 select! 循环
```

### 3.2 主循环

```text
select!
  tick:
    node = node.tick()
      → 选举超时 / 心跳 / CheckQuorum

  inbound:
    Raft(env) → node.step(env)
    Client { request, reply } →
      生成 RequestID
      client_replies[id] = reply
      step( ClientRequest{ from=to=self, request } )

  node_rx（协议出站 Envelope）:
    to == self 且 ClientResponse → 完成 reply channel → TCP ClientReply
    否则 PeerOutbox.send_raft → WireMsg::Raft
```

### 3.3 线程模型（简）

| 线程 | 工作 |
|------|------|
| 主线程 | tick / step / 出站路由 |
| accept 线程 | 接受 TCP |
| 每连接一线程 | 读帧；Client 请求同步等 reply 再写回 |

出站到 peer：懒连接 + 写超时 + 失败清连接重试一次。

## 4. raft-cli 运行时

```text
解析 --peers / --client-id / 子命令
SessionStore::load(.raft-cli-session)   // put 时 next_seq + save
对 peers 列表循环:
  TCP connect → WireMsg::Client → 等 ClientReply
Abort/IO → 换下一 peer / 下一轮（最多约 40 轮）
```

| 命令 | Request |
|------|---------|
| put | `WriteSession` |
| get / scan | `Read` |
| status | `Status` |
| members | `ChangeMembership` |

Session 文件路径 = **CLI 进程 cwd** + `.raft-cli-session`（不是 data_dir）。

## 5. 进程内 cluster（测试用）

`src/cluster/`：**不**走 TCP，用 crossbeam + 可选分区/丢包。

| API | 用途 |
|-----|------|
| `Cluster::spawn` | 多线程节点 |
| `client()` | 本地注入 Request |
| `stop` / `start` | 模拟崩溃 / 新节点 |
| `partition_*` / `set_drop_rate` | 故障注入 |

与生产部署路径分离；`cargo test` 大量使用。详见 [13](./13-故障场景与测试对照.md)。

## 6. 网络帧（回顾）

```text
u32 LE len ‖ bincode(WireMsg::{Raft, Client, ClientReply})
```

同一 `listen` 端口同时服务 **peer 协议** 与 **CLI**。
