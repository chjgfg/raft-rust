## 1. TCP 帧与 WireMsg

### 1.1 帧格式

```text
┌────────────┬─────────────────────────┐
│ u32 LE 长度 │ bincode(WireMsg)  body  │
└────────────┴─────────────────────────┘
```

长度 = body 字节数；上限 64MiB。

### 1.2 WireMsg

```rust
enum WireMsg {
    Raft(Envelope),                              // 节点间协议
    Client { id: Uuid, request: Request },       // CLI → 节点
    ClientReply { id: Uuid, response: Result<Response, Error> },
}
```

| 变体 | 方向 | 用途 |
|------|------|------|
| `Raft` | peer ↔ peer | 选举、复制、心跳、快照 |
| `Client` | cli → node | 业务请求；`id` 仅本连接相关 |
| `ClientReply` | node → cli | 与 `Client.id` 对应 |

**注意：** `WireMsg::Client` 的 `id` 与 Raft `Message::ClientRequest` 里的 `RequestID` **不是同一个**。节点进程会再生成一个 `Uuid` 作为内部 `RequestID`。

## 2. Envelope（协议信封）

```rust
struct Envelope {
    from: NodeID,   // u8
    term: Term,     // u64，发送方当前任期（PreCampaign 时为 intended term）
    to: NodeID,
    message: Message,
}
```

规则（实现侧）：

- `to` 必须是本节点，否则断言/丢弃  
- 未知 `from`（不在当前成员集合）→ 丢弃并 warn  
- 旧 `term` 消息通常丢弃；更高 `term` 使节点退回 Follower 并更新 term

## 3. Message（节点间消息）

| 变体 | 谁发 | 谁处理 | 是否落盘投票 |
|------|------|--------|--------------|
| `PreCampaign { last_index, last_term }` | Candidate(PreVote) | Follower/Candidate | **否** |
| `PreCampaignResponse { vote }` | 投票者 | Candidate(PreVote) | **否** |
| `Campaign { last_index, last_term }` | Candidate(Election) | Follower | **是**（若同意） |
| `CampaignResponse { vote }` | 投票者 | Candidate(Election) | 已在投票时落盘 |
| `Heartbeat { last_index, commit_index, read_seq }` | Leader | Follower | 否 |
| `HeartbeatResponse { match_index, read_seq }` | Follower | Leader | 否 |
| `Append { base_index, base_term, entries }` | Leader | Follower | 条目写入本地日志 |
| `AppendResponse { match_index, reject_index }` | Follower | Leader | 否 |
| `Read { seq }` | Leader | Follower | 否 |
| `ReadResponse { seq }` | Follower | Leader | 否 |
| `ClientRequest { id, request }` | 本节点注入或转发 | Leader/Follower | 见 request |
| `ClientResponse { id, response }` | Leader 或转发回程 | 本节点事件循环 | 否 |
| `InstallSnapshot { ... }` | Leader | Follower | 重置日志/状态机 |
| `InstallSnapshotResponse { last_included_index }` | Follower | Leader | 否 |

### Append 与探测

- `entries` 非空：真正复制  
- `entries` 空：探测公共 `base`（日志分叉时 `next_index` 回退）  
- 拒绝时：`reject_index != 0`，`match_index == 0`  
- 接受时：`match_index` 为匹配到的最高索引，`reject_index == 0`

## 4. Request / Response（客户端语义）

### Request

| 变体 | 含义 | 是否进 Raft 日志 |
|------|------|------------------|
| `Read(Vec<u8>)` | 状态机读命令（bincode 的 `kv::Command`） | **否** |
| `Write(Vec<u8>)` | 无 session 写 | **是** |
| `WriteSession { client_id, seq, command }` | 幂等写 | **是**（command 外再包 SESS） |
| `Status` | 集群状态 | 否 |
| `ChangeMembership { voters }` | 成员变更 | **是**（membership 字段） |

### Response

| 变体 | 内容 |
|------|------|
| `Read(Vec<u8>)` | bincode 的 `kv::Response` |
| `Write(Vec<u8>)` | 同上（如 `Put(index)`） |
| `Status(Status)` | leader/term/commit/match_index/voters… |
| `ChangeMembership { index }` | 提出的日志索引（常为 Joint 条目） |

错误：`Result` 的 `Err`，常见 `Error::Abort`（无主、切换中）→ 客户端重试。

## 5. Entry（Raft 日志条目）

```rust
struct Entry {
    index: Index,                      // 从 1 起
    term: Term,
    command: Option<Vec<u8>>,          // None = noop 或成员变更占位
    membership: Option<MembershipEntry>, // 与 command 互斥
}
```

| 场景 | command | membership |
|------|---------|------------|
| 领导当选 noop | `None` | `None` |
| 业务 Put | `Some(编码命令或 SESS+命令)` | `None` |
| 成员变更 | `None`（apply 时当 noop 推 applied） | `Some(Joint/Simple)` |

## 6. Log 在 Engine 上的键（摘要）

详见 [06](./06-BitCask与日志键空间.md)。

| Key | 编码前缀 | 值 |
|-----|----------|-----|
| `Entry(i)` | `0x00 ‖ i.to_be_bytes()` | bincode(Entry) |
| `TermVote` | `0x01` | bincode((term, Option\<NodeID\>)) |
| `CommitIndex` | `0x02` | bincode((index, term)) |
| `SnapshotMeta` | `0x03` | bincode((last_included_index, term)) |
| `SnapshotData` | `0x04` | 状态机 snapshot 字节 |

## 7. 应用层 Kv 命令

```rust
enum kv::Command {
    Get { key: String },
    Put { key: String, value: String },
    Scan,
}
enum kv::Response {
    Get(Option<String>),
    Put(Index),      // 已应用的日志索引
    Scan(BTreeMap<String, String>),
}
```

Session 写入日志时：

```text
b"SESS" ‖ bincode(SessionCommand { client_id, seq, payload })
```

`payload` 内才是 `kv::Command::Put` 的 bincode。

## 8. 节点内部跟踪结构（不在网上）

| 结构 | 角色 | 用途 |
|------|------|------|
| `Follower.forwarded` | Follower | 已转发的 RequestID，便于回程与 Abort |
| `Candidate.votes` / `phase` | Candidate | 预选票或真选票集合 |
| `Leader.progress` | Leader | 每 peer 的 match/next/read_seq |
| `Leader.writes` | Leader | 日志 index → 等待响应的客户端 |
| `Leader.reads` | Leader | 待多数确认的读队列 |
| `Leader.peer_seen` | Leader | CheckQuorum 活跃性 |
